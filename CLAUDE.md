# Hexbiblio — Project Context

Academic thesis-sharing platform: submission, browsing, comments/ratings, an AI research-advisor chatbot, and personal collections. React + TypeScript + Vite frontend, Supabase backend (Postgres, Auth, Storage, Edge Functions).

## Current infrastructure (as of 2026-07-30)

- **Frontend hosting**: Vercel, auto-deploys from the `main` branch on GitHub (`Hexbiblio/hexbiblio`). Live at `https://www.hexbiblio.vercel.app`. No custom domain yet.
- **Backend**: Supabase project ref `lstlboldqghczcomgxvv` — this is the user's own project, fully independent. **Do not confuse with `xyfsajxypbjgtceoqbkh`**, an old Lovable Cloud-managed project that is no longer used and should be treated as decommissioned.
- **AI chatbot** (`supabase/functions/thesis-chat`): calls Google's Gemini OpenAI-compatible endpoint directly (`https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`) using a `GEMINI_API_KEY` secret set in Supabase. Model is `gemini-flash-latest` (auto-updating alias) — don't hardcode a dated version string here, `gemini-2.5-flash` got deprecated once already. This replaced a call to the Lovable AI Gateway (`LOVABLE_API_KEY`) that the function had used since it was first written — that secret was never set on the independent Supabase project after the Lovable Cloud migration, so **the chatbot had been silently broken in production** until this switch. **Verified working in prod as of 2026-07-30** (both `thesis-chat` and `submit-thesis`, below, share this same secret and key). Get a `GEMINI_API_KEY` from https://aistudio.google.com/apikey and set it as a Supabase Edge Function secret if it's ever missing/rotated again.
- **Quest system** (`src/components/ThesisQuests.tsx`): a 6-step roadmap (discipline → theme → question → thesis → method → sources) tracked per-user in `localStorage` (not synced server-side beyond the profile fields each quest writes to, see `QUEST_PROFILE_FIELD`). `detectCompletedQuests` only ever checks the *next* open quest against the user's latest message — strictly sequential, a later-step cue can't skip ahead of an earlier open one. `thesis-chat` also receives `currentQuest`/`completedQuests` in the request body and is prompted to redirect the student back to the current step if their message jumps ahead, rather than just following the tangent.
- **Thesis submission integrity** (added 2026-07-30, three phases):
  - *Author lock*: `theses.author_name` is no longer free text. [SubmitThesis.tsx](src/pages/SubmitThesis.tsx) pre-fills it (disabled) from the submitter's `profiles.first_name` + `last_name`, and a Postgres trigger (`set_thesis_author_name_trigger`, migration `20260730120000_lock_thesis_author_and_antispam.sql`, re-pointed at first/last name in `20260730140000_use_first_last_name_for_thesis_author.sql`) re-derives it from the profile on every insert/update regardless of caller — can't be spoofed via a direct API call either. `profiles.username` plays no role in authorship anymore — kept only for personalization (the `thesis-chat` greeting, comment author display in `CommentSection.tsx`).
  - *Basic anti-spam*: min length + non-repetitive-abstract checks client-side ([thesisValidation.ts](src/lib/thesisValidation.ts)) and via DB `CHECK` constraints + a unique index on `(lower(title), lower(author_name))`.
  - *AI content verification*: [submit-thesis](supabase/functions/submit-thesis/index.ts) downloads the uploaded PDF, extracts text from the first ~15 pages (see gotchas below — `unpdf` has no page-range option and blows the CPU budget on real multi-page PDFs otherwise), and asks Gemini whether it matches the declared title/field/abstract before inserting into `theses`. The `theses` `INSERT` RLS policy for `authenticated` clients was dropped (migration `20260730130000_lock_theses_insert_via_function.sql`) — this function (service-role key) is the **only** path that can create a thesis row. PDF upload is accordingly mandatory. On a content mismatch, the client only ever sees a generic rejection message — Gemini's specific reasoning is logged server-side only, never returned, so a would-be spammer can't use the response to probe where the checker's line is — and the account is locked out of further submissions for 1 hour. **Both the accept and reject paths verified working in prod as of 2026-07-30.**
  - *Bibliography extraction (Phase 3)*: a `sources` table holds citations extracted from each thesis's PDF, via shared logic in [`_shared/extractSources.ts`](supabase/functions/_shared/extractSources.ts) (see gotchas below for why it locates the bibliography through the table of contents rather than a fixed page window). New submissions trigger extraction in the background from `submit-thesis` via `EdgeRuntime.waitUntil()` (never blocks the response); [extract-sources](supabase/functions/extract-sources/index.ts) backfills already-submitted theses in small batches, gated on the raw `SUPABASE_SERVICE_ROLE_KEY` as bearer token (internal/maintenance endpoint, not user-facing — never invoke it with anything other than that key). Browsable at `/sources` ([Sources.tsx](src/pages/Sources.tsx), filterable by the parent thesis's field/degree) and as a compact numbered list on each thesis's own detail page.
- **Auth providers**: Email/password (native Supabase) and Google OAuth (native `supabase.auth.signInWithOAuth`, configured with the user's own Google Cloud OAuth client). Apple sign-in is **intentionally hidden** in `src/pages/Auth.tsx` (commented out) — the user doesn't have a paid Apple Developer account yet. Re-enabling it requires that account plus a Services ID / Team ID / Key ID setup in Supabase's Apple provider.
- **SPA routing on Vercel**: [vercel.json](vercel.json) has a catch-all rewrite (`/(.*)` → `/index.html`) — without it, refreshing or directly linking to any client-side route (e.g. `/sources`, `/database/:id`) hit Vercel's own 404 page instead of the app, since only `index.html` exists as a real file and React Router (`BrowserRouter`) handles the rest client-side.
- **Local dev**: project lives at `/Users/simonlegall/Desktop/All Inside/HexBiblio/Code/hexbiblio` on the user's Mac. `.env` is gitignored — recreate locally with the project's real `VITE_SUPABASE_*` values if missing (ask the user, don't guess).

## History worth knowing

- The project was originally built and hosted entirely on **Lovable** (Lovable Cloud managed backend + `*.lovable.app` hosting + a proprietary `@lovable.dev/cloud-auth-js` OAuth wrapper). All of that has been fully migrated away:
  - Hosting moved to Vercel.
  - Database/auth/storage migrated from the Lovable-managed Supabase project to the user's own project (`lstlboldqghczcomgxvv`), via a `pg_dump`/`pg_restore` export-and-restore of the `public` schema, `auth.users`/`auth.identities`, and storage bucket configs. Real user accounts (passwords included) survived the migration intact.
  - The Lovable proprietary Google/Apple OAuth wrapper was replaced with native `supabase.auth.signInWithOAuth`.
  - Lovable Cloud has since been (or is about to be) fully disconnected in Lovable's own UI (Cloud → Advanced settings → Remove Lovable Cloud).
- A security audit was done and fixed:
  - `thesis-chat` previously had **no real auth check** (always sent the shared anon key, never the caller's session token) and **no server-side rate limiting** — only a client-side, trivially-bypassable guest limit. Fixed: the function now verifies the caller's JWT via `supabase.auth.getUser()`, rate-limits by `user_id` (logged in) or `guest:<ip>` (anonymous) using a `chat_logs` table, and re-fetches the caller's profile server-side instead of trusting a client-supplied `profile` field.
  - The `theses` storage bucket had no file-size/MIME restrictions and its upload policy let any authenticated user upload into any other user's folder. Fixed: capped at 20MB/PDF-only, upload policy now checks `auth.uid() = (storage.foldername(name))[1]`.
  - `.env` was previously committed to the GitHub repo. It's now gitignored (values there are the public/anon Supabase key, not high-severity, but still cleaned up).
- On 2026-07-29, a burst of rapid automated test requests against live `thesis-chat` got the Google Cloud project behind `GEMINI_API_KEY` **permanently denied access** by Google (abuse detection, not quota/billing). Recovered by generating a new key under a different Google account. A project skill, `.claude/skills/thesis-chat-testing-safety/SKILL.md`, now enforces human-like spacing (~3-5s minimum) between any live test calls to *any* AI endpoint in this project — read it before testing `thesis-chat` or `submit-thesis` live.
- On 2026-07-30, the user pasted a live `service_role` key (full admin DB access) directly into chat while sharing a `curl` command for the `extract-sources` backfill endpoint. Flagged immediately and rotated from the dashboard. Same pattern as an earlier exposed Google OAuth client secret (below) — when asking the user to run an authenticated `curl`/CLI command, ask for the **output only**, never the full command if it embeds a credential.

## Conventions / gotchas for future work

- Supabase's web SQL Editor does **not** support `COPY ... FROM stdin` blocks (psql-only) — any raw SQL given to the user to paste there must use plain `INSERT INTO ... VALUES (...)` statements.
- Don't manually cast JSON-shaped text (`{"key": "value"}`) to `::text[]` just because it starts with `{` — that broke `auth.users.raw_app_meta_data`/`raw_user_meta_data` (jsonb) during the migration. Let Postgres coerce plain string literals to the target column type instead.
- `storage.buckets`/`storage.objects` have a `protect_delete` trigger — direct `DELETE` on them is blocked by Supabase; use `ON CONFLICT DO NOTHING` on insert instead of delete-then-reinsert patterns.
- The user is comfortable following precise step-by-step instructions (GitHub web UI, Supabase dashboard, Google Cloud Console) but had no prior local git/terminal experience — this local clone is their first. Keep terminal commands explicit and check in after each one rather than batching many steps.
- **Supabase Storage keys must be S3-safe ASCII** — accented characters (very common in French filenames, e.g. "Mémoire.pdf") and other non-ASCII characters are rejected outright with `Invalid key`. Sanitize filenames (strip diacritics, e.g. via `.normalize("NFD")` + stripping combining marks, then swap any other unsafe character for `_`) before using them in a storage path — see `sanitizeFileName` in [SubmitThesis.tsx](src/pages/SubmitThesis.tsx).
- **`npx supabase db push --linked` fails** with a `permission denied to alter role` / login-role error — known unresolved CLI bug ([supabase/cli#5091](https://github.com/supabase/cli/issues/5091)). Workaround: `npx supabase db push --db-url "postgresql://postgres:PASSWORD@db.lstlboldqghczcomgxvv.supabase.co:5432/postgres"` (direct connection string from Dashboard → **Connect** button → **Direct** tab; DB password is separate from the anon/service_role keys — reset it from Project Settings → Database if never saved). If a migration was ever applied out-of-band (e.g. pasted into the SQL Editor), `db push` will try to re-run it and fail unless it's idempotent — mark it as already applied with `npx supabase migration repair --status applied <version> --db-url "..."` instead of re-running it. Write new migrations with `IF EXISTS`/`IF NOT EXISTS` guards where possible to avoid ever needing this.
- **`unpdf`'s `extractText()` has no page-range option** — it walks every page of a PDF, which reliably exceeds a Supabase edge function's per-request CPU budget on a real 80-150 page thesis (`Error 546`, Supabase's `WORKER_LIMIT`). Extract text page-by-page instead (`pdf.getPage(n)` + `page.getTextContent()` on the `PDFDocumentProxy` from `getDocumentProxy()`), stopping at a fixed page count — see `extractLeadingText` in [submit-thesis/index.ts](supabase/functions/submit-thesis/index.ts).
- **Don't locate a section of a long PDF by guessing a fixed page window** (e.g. "the bibliography is somewhere in the last N pages") — real theses can carry huge annexes after it (one seen in this project: bibliography at page 82 of 227, followed by 140+ pages of interview transcripts), so any fixed window eventually misses it. Read the table of contents instead (always near the front, cheap and bounded) for the stated page number, validate against the actual heading nearby, and only fall back to a backward scan / blind guess if that fails — see `findBibliographySection` in [`_shared/extractSources.ts`](supabase/functions/_shared/extractSources.ts).
